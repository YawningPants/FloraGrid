# 两层花丛性能评估（2026-10-26）

当前上限按窗口宽度设为 10 / 14 / 18 株；前排为 6 / 8 / 10 株，其余为后排。两个 SVG 图层各用三组共享摇曳动画，共六组。后排透明度为前排的 0.52，花头缩小至 0.86；没有为每朵花创建持续摇曳动画或模糊滤镜。

新增完成任务进入前排，前排较早完成的花淡入后排；超出上限时，移除后排中最早的一朵。撤销完成或删除后，从未显示的较早完成任务中补入后排；补入只淡入，避免抢走用户注意。位置缓存仍固定保留已有花的位置，留出八个备用锚点。

## 样本与结果

运行 `node tools/perf/header-garden.mjs --layers`，使用独立 Chrome 配置、合成任务和真实前端。390 × 900、600 × 900，2 倍像素，16 个逻辑处理器；静置 CPU 采样与帧间隔探针分开执行。

对照使用**同一两层实现、旧 6/8/12 数量上限**，用来观察额外花朵的开销，并非旧程序的历史二进制。

| 场景                        | 花朵 | JS 堆 MiB | 进程组 CPU 占单核 | 同步完成中位数 ms | RAF 间隔 P95 ms |
| --------------------------- | ---: | --------: | ----------------: | ----------------: | --------------: |
| 750 项，390px，对照数量上限 |    8 |     2.020 |            11.67% |              6.75 |            16.8 |
| 750 项，390px，静态扩容花丛 |   14 |     1.884 |             0.26% |              未测 |            16.8 |
| 750 项，390px，扩容摇曳花丛 |   14 |     2.047 |            10.63% |              7.00 |            16.8 |

两组摇曳样本 CPU 的差异处于噪声范围，不能据此声称扩容降低了开销。额外花朵使 JS 堆约增加 0.027 MiB；JS 堆不包含所有 DOM、图片解码、原生 WebView 或 GPU 资源，不能当成整机内存。

600px 宽窗口显示 18 株，花丛共有 451 个 SVG/容器元素，进程组 CPU 约占单核 10.4%，约为本机总 CPU 的 0.65%。390px 的后台暂停样本主线程约 0.71ms/3s，样本内 Script 和 Style/Layout 增量为零；后台暂停机制保留。

RAF 的 16.8ms 是屏幕帧间隔，不是每帧执行了 16.8ms JavaScript。同步完成耗时也不包含整个生长动画持续时间。上述为隔离浏览器测量，不代表 Tauri 发布版驻留内存或 GPU 功耗。

在本机样本下，10/14/18 的扩容幅度可接受；不建议继续无界增加。关闭花丛、系统减少动态效果以及失焦/最小化暂停仍然有效。
