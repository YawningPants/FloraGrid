# 备份、恢复与迁移

## 导出备份 / 换电脑

1. 打开 **设置 → 数据 → 导出备份**。
2. 选择保存位置，得到一个 JSON 文件。
3. 将文件复制到新电脑，安装日枝后，在 **设置 → 数据 → 导入备份** 中选择它。
4. 查看日程、任务、长期任务、标签分组和提醒的数量，再确认恢复。可以选择是否恢复外观。

备份包括所有日期的任务树、任务状态、任务颜色、标签快照、花朵信息、每日随笔、长期任务库、长期标签分组、提醒规则和历史例外，以及外观设置。不会包含程序安装文件、缓存或其他无关文件。

**导入采用完整恢复，会替换当前日枝数据。** 当前有数据时，会先在当前数据文件夹中保存 `rizhi-before-change-*.json` 安全副本，完成后显示其位置。无关文件保留。取消确认不会写入数据；无效、不兼容或空备份会被拒绝。

当前整库备份支持至多 100 MiB。备份格式为 `rizhi-backup` 版本 1，保留完整 JSON 字段，不经过文本格式转换。

## 更换存储文件夹

1. 在 **设置 → 数据** 点击“更换文件夹”，或恢复默认位置。
2. 日枝检查目标是否为空；非空时显示提示。
3. 默认勾选“将当前数据一并迁移”。取消勾选后仅切换位置，原数据保留。
4. 迁移时展示进度，写入后重新核验，再切换应用的存储位置。
5. 完成后可保留原数据，或经过额外确认清理原数据。

如果选择迁移到非空文件夹，冲突的同一天记录、长期任务库、标签和提醒规则以当前文件夹中的文件为准；目标中其他日期以及无关文件会保留。覆盖前会在目标文件夹中生成安全备份。此操作不逐条合并同一天的任务或两个任务库。

迁移的两个文件夹不能互相包含，不能是同一位置。数据文件中的目录链接也会被拒绝，以避免意外写入其他位置。

清理只删除本次已经迁移并核验一致的日枝数据文件，保留原文件夹、自动备份和其他文件。如果原文件或新文件已被修改，日枝会停止清理并保留原数据。清理凭证仅在本次应用运行期间有效。

## 多窗口和中断

执行整库操作前，各个日视图会保存待写入的修改，长期任务也会等待保存完成。尚未保存的提醒、长期任务编辑或长期标签草稿需要先处理；数据操作期间相关窗口暂时停止编辑，成功后刷新。

导入和迁移使用恢复日志。如果写入中失败，会恢复操作前的日枝文件；意外中断后，下次读取该文件夹时会先完成恢复。磁盘损坏、权限丢失等导致无法恢复时，应保留整个文件夹和安全备份，不要手动删除日志。

## 手动备份

也可以退出应用后复制“设置 → 数据”中显示的整个数据文件夹。它包括 `days/`、`long-tasks.json`、`tag-templates.json` 和 `reminders.json`。外观偏好存储在应用偏好中，手动复制数据文件夹不包含外观；使用导出备份可以一并保存外观。

## 开发验证

`npm test` 包含备份格式和浏览器写入失败回滚测试；`cargo test --lib --manifest-path src-tauri/Cargo.toml` 包含文件事务、中断恢复和路径校验。

`npm run test:release-features` 使用隔离的无头浏览器检查纸页配色、精简子任务、跨月禁用、叶片连接及数据操作的确认和进度界面。

真实桌面端测试先运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/perf/build-native-profile.ps1 -DataTransfer`，再运行 `node tools/qa/data-transfer-native.mjs`。三个测试窗口均隐藏，使用随机独立应用标识和 `src-tauri/target/` 下的合成数据，脚本核对标识后才写入，不接触现有用户日程。
